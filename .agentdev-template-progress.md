## Choices

- **Workflow: B (merge into an existing repository).** Dr.QP is a ROS 2 colcon
  workspace with its own source, CI, devcontainer, and lint configuration, and
  it is the repository the template was originally extracted from. Workflow A
  would overwrite all of that.
- **Upstream is `plume-works/agent-devcontainer`.** The prior spike under
  `docs/agents/specs/agent-devcontainer-migration/` names `chocobot-farm`; the
  organization has since been renamed. Treat that spike's org references, and
  its one-shot conclusions generally, as stale.
- **Optional bundle `custom-image`: retained, and the image is rebased on
  `agent-desktop`.** Dr.QP keeps publishing its own ROS development image, but
  `FROM`s the published `agent-desktop` so only the ROS delta is built locally.
  Follows the spike's `01-base-image-migration.md`; its finding F7 (nothing
  rebuilds Dr.QP's image when `agent-desktop:edge` moves) must be resolved with
  a Renovate digest pin as part of that work, not after it.
- **Optional bundle `knowledge-base`: adopted.** The `.iwe/` scaffold and
  `docs/knowledge/` project memory are taken, seeded from `templates/iwe/data/`
  at the adopted ref, then onboarded with `/agentdev:iwe-setup` and
  `/agentdev:iwe-map`. The existing `docs/agents/specs/` tree is consumer-owned
  prose and is left exactly as it is — IWE is added alongside it, not over it.
- **Agent catalog: deduplicated against the installed `agentdev` plugin.** The
  general skills and agents the plugin now provides are deleted from `.claude/`;
  the ROS- and project-specific ones are kept. This is the plugin route the
  spike's finding F8 recommended once the general catalog stabilized.
- **Ruff configuration stays in this repository's `ruff.toml`.** The template's
  `.ruff.toml` is NOT copied: ruff resolves `.ruff.toml` before `ruff.toml` and
  stops, so dropping it in would silently disable this repo's 99-character
  limit, ROS `known-third-party` isort grouping, and `packages/vendor`
  exclusion, with no warning. Wanted rules are merged into the existing
  `ruff.toml` instead.
- **Credential volume: the template default `agentdev-agents-auth` is adopted**,
  sharing only Claude Code's and Codex's credentials across this project, its
  worktrees, and other projects using the same volume name.
- **`.ruff.toml` is deliberately not in `tracked_paths`.** This consumer keeps
  its ruff configuration in `ruff.toml`, so an upstream `.ruff.toml` change
  cannot be applied mechanically. `check-updates.sh` skips a tracked path that
  exists upstream but not locally, so listing it would be a silent no-op
  anyway. When an update episode touches lint configuration, diff upstream
  `.ruff.toml` by hand and merge wanted rules into `ruff.toml`.
- **`.markdownlint.yml` not adopted.** Super-Linter formats markdown here with
  `VALIDATE_MARKDOWN_PRETTIER`, so the config would have no matching hook.
- **The `custom-image` bundle is retained but its paths are not tracked.** This
  repository builds its own ROS image from `docker/ros/` and
  `docker/ros/ansible/`; those are consumer source that merely occupies the
  same role as the template's `docker/` and `ansible/`, not copies of them.
  Diffing them against the template's `agent-desktop` build would be pure
  noise, so `docker/`, `ansible/`, `ansible.cfg` and `.dockerignore` are
  omitted from `tracked_paths` while `optional_bundles` still records the
  bundle as kept.
- **`py_packages/validate_agent_files` is kept for now**, against the guide's
